## Question 6.21

Explain why bearer token authentication is preferred for API routes over session-based authentication.

---

**Answer:**

Bearer tokens are the preferred method of token authentication for several reasons: 

First, APIs are stateless, this means that they do not keep user sessions or maintain any user session details on the server side.

Second, bearer tokens are universal meaning they can be used on any platform, not just web browsers.

Third, since they don't include cookies, there is no need to worry about CSRF or cross-domain request issues.

---

Fourth, session based authentication is more scalable because there is no server memory required to hold sessions.

Fifth and finally, the authentication information is included in the requests via the Authorization: Bearer header.

Session based authentication relies on cookies, server side session storage and browser specific behavior, making it a less than appropriate method for API use cases.

## Question 6.22

Describe the complete process of setting up a secure API endpoint from scratch, including authentication.

---

**Answer:**

1. Install Sanctum
composer require laravel/sanctum
php artisan vendor:publish --provider="Laravel\Sanctum\SanctumServiceProvider"
php artisan migrate

1. Add HasApiTokens to the User model
use Laravel\Sanctum\HasApiTokens;

class User extends Authenticatable {
    use HasApiTokens, Notifiable;
}

---

3. Protect routes using Sanctum middleware

In routes/api.php:

Route::middleware('auth:sanctum')->get('/profile', function (Request $request) {
    return $request->user();
});

4. Create tokens upon login or registration
$token = $user->createToken('api-token')->plainTextToken;
return ['token' => $token];

---

5. Make authenticated API requests

Clients must include:

Authorization: Bearer YOUR_TOKEN

6. Build the secure endpoint
Route::middleware('auth:sanctum')->get('/dashboard', [DashboardController::class, 'index']);

This ensures only authenticated users with valid tokens can reach the endpoint.

## Question 6.23

Compare the advantages and disadvantages of public API endpoints versus protected API endpoints.

---

**Answer:**

Public API Endpoints

**Pros:**

Open access — no authentication required

Convenient for third-party developers

Great for public data (e.g., weather, product lists, documentation)

**Cons:**

No user identity or personalization

Higher risk of abuse (i.e. spam, scraping, DDoS)

Must rely on rate limiting and throttling

---

Protected API Endpoints

**Pros:**

Secure — Only authorized clients can access

Supports user-specific data and actions (e.g., login/log out, purchase history)

Enables auditing and logging

Prevents abuse through authentication and permissions

**Cons:**

Must manage tokens

More complex implementation

Clients must securely store tokens
