## Question 4.16

Explain the difference between web routes (`/student`) and API routes (`/api/student`) in terms of purpose and response format.

---

**Answer:**

Web routes like `/student` are intended for traditional web pages which return HTML views, intended for users to interact with using a web browser. They should typically serve things like pages, forms or templates. 

API routes like `/api/student` are meant for the exchange of data, with the route responding with a JSON structure that is usable by other applications or JavaScript front ends. Both types of routes could make use of the same controller logic, but the web routes serve a rendered view for humans, and API routes are a structured format for programs or front-end frameworks.

## Question 4.17

Describe how Laravel automatically handles route parameters like `{id}` in routes and passes them to controller methods.

---

**Answer:**

The framework automatically captures the value from the URL and passes it to the corresponding controller method as an argument.

In this example: /student/123 the framework takes 123 and passes it to the contoller to get our output: `<h1>Student ID: 123</h1>`

routes/web.php

```php
Route::get('/student/{id}', [StudentController::class, 'show']);
```

Controller Method:

```php
public function show($id){
    return '<h1>Student ID: ' . $id . '</h1>';
}
```
