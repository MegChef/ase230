# Q1. GitHub.io Manual Deployment

---

## Question 1.1

What is GitHub Pages in simple terms?

---

**Answer:**

- GitHub Pages is a free service that hosts websites directly from your GitHub repository.

---

## Question 1.2

What is the difference between static and dynamic site hosting?

---

**Answer:**

- Static hosting serves pre-generated HTML files, while dynamic hosting runs server-side code (like PHP, Node, or databases) to generate pages on the fly.

---

## Question 1.3

What must your repository be named for GitHub Pages user pages?

---

**Answer:**

- `yourusername.github.io`

---

## Question 1.4

What command builds your Hugo site and where are the files stored?

---

**Answer:**

- `hugo`
- Files are stored in the public/ folder.

---

## Question 1.5

Complete this sequence for manual deployment:

1. Build Hugo site: `hugo`
2. Copy files: `cp -r public/* ../yourusername.github.io/`
3. Navigate to repo: `cd ../yourusername.github.io`
4. Add files: `_____`
5. Commit: `_____`
6. Push: `_____`

---

**Answer:**

git add .
git commit -m "Deploy site"
git push

---

## Question 1.6

Where do you configure GitHub Pages in your repository?

---

**Answer:**

- In Settings → Pages.

---

## Question 1.7

What are the GitHub Pages configuration options for Source?

---

**Answer:**

- main or master branch
- /root directory
- /docs folder

---

## Question 1.8

How long does it typically take for GitHub Pages to deploy after pushing?

---

**Answer:**

- Usually 30–60 seconds.

---

## Question 1.9

Complete this URL mapping for GitHub Pages:

Repository file → Website URL

- `index.html` → `_____`
- `about/index.html` → `_____`
- `projects/student-api/index.html` → `_____`

---

**Answer:**

index.html → https://yourusername.github.io/

about/index.html → https://yourusername.github.io/about/

projects/student-api/index.html → https://yourusername.github.io/projects/student-api/

---

## Question 1.10

What can GitHub Pages host and what can't it host?

---

**Answer:**

Can host:

- Static files (HTML, CSS, JS, images)
- Static site generators (Hugo, Jekyll, etc.)

Cannot host:

- Server-side code (PHP, Node, Python)
- Databases or dynamic back-end features

---

## Question 1.11

How do you test your built Hugo site locally before deploying?

---

**Answer:**
Open the public/index.html file in a browser or run a small local server, such as:

- `hugo server -D`

---

## Question 1.12

What should you check after your site goes live?

---

**Answer:**

- All pages load correctly
- Navigation links work
- Images/CSS/JS load
- Correct URLs (no broken links)
- Mobile responsiveness

---

## Question 1.13

What is the manual update process when you change your Hugo site?

---

**Answer:**

- Rebuild site with hugo
- Copy updated public files to GitHub Pages repo
- Commit and push changes

---

## Question 1.14

What's the difference between User/Organization Pages and Project Pages?

---

**Answer:**

User/Org Pages: Hosted from yourusername.github.io repo; domain is the username.

Project Pages: Hosted from any repo; domain becomes yourusername.github.io/reponame.

---

## Question 1.15

Why do you need to set the repository to public for GitHub Pages?

---

**Answer:**

GitHub Pages cannot serve websites from private repositories (except on paid plans), so the repo must be public for hosting.
