# Q2. GitHub Actions Basics

---

## Question 2.1

What is GitHub Actions in simple terms?

---

**Answer:**

- GitHub Actions is an automation tool that runs tasks (like building or deploying your site) automatically whenever you push code.

---

## Question 2.2

What is the difference between manual deployment and GitHub Actions?

---

**Answer:**

- Manual deployment requires you to build and upload files yourself, while GitHub Actions automatically builds and deploys your site every time you push.

---

## Question 2.3

Complete this simple GitHub Actions workflow:

```yaml
name: Say Hello
on: _____    # When someone pushes code
jobs:
  greet:
    runs-on: _____
    steps:
      - name: Say Hello
        run: echo "_____"
```

---

**Answer:**

```yaml
name: Say Hello
on: push    # When someone pushes code
jobs:
  greet:
    runs-on: ubuntu-latest
    steps:
      - name: Say Hello
        run: echo "Hello World"
```

---

## Question 2.4

Where must GitHub Actions workflow files be located?

---

**Answer:**

- In the .github/workflows/ directory.

---

## Question 2.5

What are the 4 key concepts in GitHub Actions?

---

**Answer:**

- Workflows
- Jobs
- Steps
- Actions

---

## Question 2.6

What does this workflow structure mean?

```yaml
build-website:
  runs-on: ubuntu-latest
  steps: [list of actions]
```

---

**Answer:**

- It defines a job named build-website that runs on an Ubuntu virtual machine and performs the listed steps.

---

## Question 2.7

What are three types of GitHub Actions triggers?

---

**Answer:**

`push` (when code is pushed)
`pull_request`
`schedule` (cron jobs)

---

## Question 2.8

How do you access the GitHub Actions dashboard?

---

**Answer:**

- Go to your repository → click the Actions tab.

---

## Question 2.9

What do these GitHub Actions status indicators mean?

- ✅ Build Hugo Site - Completed
- 🟡 Build Hugo Site - Running  
- ❌ Build Hugo Site - Failed

---

**Answer:**

✅ Completed: The workflow finished successfully
🟡 Running: The workflow is currently in progress
❌ Failed: The workflow stopped due to an error

---

## Question 2.10

What is the conceptual workflow for Hugo website automation?

---

**Answer:**

1. Detect a push
2. Build the Hugo site
3. Upload the generated files
4. Deploy to GitHub Pages automatically

---

## Question 2.11

What are the three main types of GitHub Actions?

---

**Answer:**

- Workflow actions (in your repo)
- Marketplace actions
- Custom actions you create

---

## Question 2.12

Complete the steps for creating your first GitHub Action:

1. Create folder: `_____`
2. Create file: `hello.yml`
3. Add workflow code
4. Commands: `git add .` → `_____` → `_____`
5. Check: Actions tab to see it run

---

**Answer:**

1. Create folder: `.github/workflows`
2. Create file: `hello.yml`
3. Add workflow code
4. Commands:
`git add .` → `git commit -m` "Add workflow" → `git push`
5. Check Actions tab

---

## Question 2.13

Why are GitHub Actions considered "professional development practices"?

---

**Answer:**

- Because automated builds, tests, and deployments are core parts of modern DevOps workflows used in real production environments.

---

## Question 2.14

What is the timeline for GitHub Actions execution?

---

**Answer:**

- Triggers instantly after a push
- Workflow starts within a few seconds
- Most builds finish within 10–60 seconds
