# Q3. GitHub Actions: Using Pre-Built Actions

---

## Question 3.1

What is the difference between `run:` and `uses:` in GitHub Actions?

---

**Answer:**

run: executes a shell command (bash commands like echo, npm install, hugo).

uses: loads a pre-built GitHub Action created by GitHub or the community.

---

## Question 3.2

What does this action name format mean?
```yaml
uses: actions/checkout@v4
```

---

**Answer:**

- This uses the checkout action from the actions organization, version v4.

---

## Question 3.3

What are the three key pre-built actions needed for Hugo deployment?

---

**Answer:**

- `actions/checkout` – download repo code
- `actions/configure-pages` – configure GitHub Pages
- `actions/deploy-pages` – deploy the built site

---

## Question 3.4

What does `actions/checkout@v4` do and why do you need it?

---

**Answer:**

- It downloads your repository’s files into the workflow runner so the workflow can build, test, or deploy them.

---

## Question 3.5

Complete this workflow using pre-built actions:

```yaml
steps:
  - name: Download code
    uses: _____
  
  - name: Setup Pages
    uses: _____
  
  - name: Build with Hugo
    run: _____
  
  - name: Deploy to GitHub Pages
    uses: _____
```

---

**Answer:**

```yaml
steps:
  - name: Download code
    uses: actions/checkout@v4
  
  - name: Setup Pages
    uses: actions/configure-pages@v4
  
  - name: Build with Hugo
    run: hugo
  
  - name: Deploy to GitHub Pages
    uses: actions/deploy-pages@v4
```

---

## Question 3.6

What is the purpose of the `with:` parameter in GitHub Actions?

---

**Answer:**

- It supplies configuration options or inputs to an action.

---

## Question 3.7

Give an example of using `with:` parameters:

---

**Answer:**

```yaml
uses: actions/setup-node@v4
with:
  node-version: '18'
```

---

## Question 3.8

What is the purpose of `id:` in GitHub Actions and how is it used?

---

**Answer:**

- It gives a step a name so other steps can reference its outputs.
  
```yaml
id: build
run: echo "tag=1.0" >> $GITHUB_OUTPUT
```

`echo ${{ steps.build.outputs.tag }}`

---

## Question 3.9

Why should you use pre-built actions instead of writing everything yourself?

---

**Answer:**

- They are reliable, maintained, secure, tested, and save you from writing complex code.

---

## Question 3.10

Compare writing custom deployment vs using pre-built actions:

---

**Answer:**

Custom: Takes longer, error-prone, must maintain yourself

Pre-built: Ready to use, trusted, faster, industry-standard

---

## Question 3.11

Where do you find GitHub Actions and how do you choose good ones?

---

**Answer:**

Find them in the GitHub Marketplace.

Choose actions that are official, well-documented, frequently updated, and widely used.

## Question 3.12

Complete this professional Hugo deployment workflow:

```yaml
jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: _____
        with:
          submodules: recursive
      
      - name: Setup Hugo
        uses: _____
        with:
          hugo-version: 'latest'
      
      - name: Setup Pages
        uses: _____
      
      - name: Build
        run: _____
      
      - name: Deploy
        uses: _____
```

---

**Answer:**

```yaml
jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          submodules: recursive
      
      - name: Setup Hugo
        uses: peaceiris/actions-hugo@v2
        with:
          hugo-version: 'latest'
      
      - name: Setup Pages
        uses: actions/configure-pages@v4
      
      - name: Build
        run: hugo
      
      - name: Deploy
        uses: actions/deploy-pages@v4
```

## Question 3.13

What would happen if you tried to write the deployment code yourself instead of using `actions/deploy-pages@v2`?

---

**Answer:**

You would need to manually handle authentication, create artifacts, upload files, manage permissions, and ensure correctness. It becomes error-prone and far more complicated.

- `peaceiris/actions-hugo` — installs Hugo
