# Q4. Hugo to GitHub.io Automatic Deployment

---

## Question 4.1

What is the key difference between manual deployment and automatic deployment for Hugo?

---

**Answer:**

Manual deployment requires you to run `hugo`, generate `public/`, and upload it yourself. Automatic deployment uses GitHub Actions to build and publish your site every time you push—no manual steps.

---

## Question 4.2

Why do you copy Hugo source files instead of the public/ directory for automatic deployment?

---

**Answer:**

Because GitHub Actions needs the source files to build the site automatically. The `public/` folder is generated by Hugo and should not be tracked or uploaded manually.

---

## Question 4.3

What must you configure in hugo.toml for GitHub Pages deployment?

---

**Answer:**

Set the correct baseURL

Example:
baseURL = "https://username.github.io/"

---

## Question 4.4

Complete these essential permissions for GitHub Actions to deploy pages:

```yaml
permissions:
  contents: read
  pages: _____
  id-token: _____
```

---

**Answer:**

```yaml
permissions:
  contents: read
  pages: write
  id-token: write
```

---

## Question 4.5

Why do you need to use Hugo version 0.134.0 or later in the workflow?

---

**Answer:**

Because GitHub Pages requires the new deployment system that supports OIDC authentication and the Pages build process, which Hugo 0.134.0+ is compatible with.

## Question 4.7

What GitHub Pages source setting should you use for automatic deployment?

---

**Answer:**

- "GitHub Actions" (not a branch).

---

## Question 4.8

What should be included in your .gitignore file for Hugo?

---

**Answer:**

- `public/`
- `resources/`
- `.hugo_build.lock`
- Any theme submodule build files

---

## Question 4.9

Why do you ignore the public/ directory in .gitignore?

---

**Answer:**

Because it is a generated folder produced by Hugo—GitHub Actions will rebuild it, so committing it is unnecessary and creates merge conflicts.

---

## Question 4.10

What should you check before deploying your Hugo site with GitHub Actions?

---

**Answer:**

- Your site builds locally without errors
- baseURL is correct
- .gitignore excludes public/
- Workflow YAML is valid
- GitHub Pages is set to use “GitHub Actions”

---

## Question 4.11

What is the typical deployment timeline for automatic Hugo deployment?

---

**Answer:**

- 1–3 minutes after you push changes.

## Question 4.13

What repository structure is used for automatic Hugo deployment?

---

**Answer:**

A single repository containing all Hugo source files. GitHub Actions builds into a temporary artifact and publishes to GitHub Pages automatically.

---

## Question 4.14

What happens during the automatic deployment process?

---

**Answer:**

1. Checks out your code
2. Installs Hugo
3. Builds the site
4. Uploads the artifact
5. Deploys it to GitHub Pages

---

## Question 4.15

What are common issues and their solutions for Hugo deployment?

---

**Answer:**

- Wrong baseURL → Site loads without CSS
- public/ committed → Conflicts; remove it and ignore it
- Wrong Pages source → Set to GitHub Actions
- Old Hugo version → Update to 0.134.0+
- Submodules not loading → Enable submodules: recursive

---

## Question 4.16

What Hugo configuration optimizes the site for GitHub Pages?

---

**Answer:**

```toml
baseURL = "https://username.github.io/"
enableGitInfo = true
minify = true
```
