# Q2. Docker and PHP

---

## Question 2.1

What command runs PHP 8.2 in a Docker container and displays the PHP version?

---

**Answer:**

- `docker run -it php:8.2-cli php --version`

---

## Question 2.2

What does the `-v $(pwd):/app` flag do in a Docker command?

---

**Answer:**

- `-v $(pwd):/app`: Mount current directory to /app  in container
- It mounts your current directory into the container at /app, allowing Docker to access your local files.
  
---

## Question 2.3

Complete this Docker command to run a PHP script called `api.php` using PHP 8.2:

```bash
docker run --rm -v $(pwd):/app -w /app php:8.2-cli _____
```

---

**Answer:**

 ```bash
docker run --rm -v $(pwd):/app -w /app php:8.2-cli php api.php
```

---

## Question 2.4

What does the `-p 8000:8000` flag do in this Docker command?

```bash
docker run --rm -p 8000:8000 -v $(pwd):/app -w /app \
  php:8.2-cli php -S 0.0.0.0:8000
```

---

**Answer:**

- `-p 8000:8000`: Map port 8000 from container to host
- It maps port 8000 on your computer to 8000 in the container, allowing you to access the PHP server from your web browser.
  
---

## Question 2.5

Write a simple Dockerfile that uses PHP 8.2-cli, sets working directory to `/app`, copies all files, exposes port 8000, and starts a PHP server:

---

**Answer:**

```bash
# Dockerfile
FROM php:8.2-cli
# Set working directory
WORKDIR /app
# Copy PHP files
COPY . .
# Expose port 8000
EXPOSE 8000
# Start the PHP built-in server
CMD ["php", "-S", "0.0.0.0:8000"]
```

---

## Question 2.6

What commands build and run a Docker image named `my-php-app`?

---

**Answer:**

```php
# Build image with tag "my-php-app"
docker build -t my-php-app .
```

```php
# Much simpler!
docker run --rm -p 8000:8000 my-php-app
```

---

## Question 2.7

In a Dockerfile, what is the difference between these two approaches?

```dockerfile
# Approach 1
COPY . .

# Approach 2
# Use volume mapping: -v $(pwd):/app
```

---

**Answer:**

- COPY . .
Copies files into the image permanently at build time.

- Volume mapping (-v)
Shares your local files with the container live, allowing instant code changes without rebuilding.

---

## Question 2.8

What does `FROM php:8.2-cli` specify in a Dockerfile?

---

**Answer:**

- It specifies the base image, meaning your container starts with PHP 8.2 CLI already installed.

---

## Question 2.9

Why would you use Docker for PHP development instead of installing PHP directly on your computer?

---

**Answer:**

- Avoid installing multiple PHP versions locally

- Consistent environments across computers

- No “works on my machine” issues

- Clean, isolated development without breaking your OS

---

## Question 2.10

What is the purpose of the `WORKDIR /app` instruction in a Dockerfile?

---

**Answer:**

It sets the default working directory so all commands run inside `/app` automatically.

---

## Question 2.11

How do you test a Docker build locally without using the development server?

---

**Answer:**

Run the container and execute a script directly:

```bash
docker run --rm my-php-app php --version
```

or run any test script included in the image.

---

## Question 2.12

What happens when you run `docker build -t my-app .` followed by `docker run --rm -p 8000:8000 my-app`?

---

**Answer:**

- The build command creates an image called my-app from the Dockerfile

- The run command starts a container from that image and exposes port 8000 so you can access the running app
